# blog_create · 博客生成器

给小七の杂谈用的发文工具。在浏览器里写 Markdown（或直接贴 HTML），右侧实时预览真实排版，一键生成
`blog/xxx.html`，同时自动维护「上一篇 / 下一篇」「同分类上一篇 / 下一篇」、`blog.html` 与分类页的文章列表。

## 相比旧版改了什么

| 项目 | 旧版 | 现在 |
| --- | --- | --- |
| 正文 | 只能手写 HTML，没有预览 | Markdown + 原始 HTML 混排，实时预览 |
| 工具栏 | 4 个按钮（B / I / P / Img） | 标题、列表、引用、代码块、表格、图片宽度、居中、红色强调，外加「更多格式 ▾」 |
| 分类 | 文本输入，提示不明显 | 直接读取 `blog.html` 的分类做成芯片，可多选、显示篇数与对应分类页 |
| 文章列表 | 需要手动往 `blog.html`、`xxx_blogs.html` 里加条目 | 发布时自动按日期插入（置顶保持最前，多分类会写进每个分类页） |
| 上下篇 | 只改“上一篇”那一篇，且只认“没有了” | 按全站顺序重算，两篇邻居一起更新，补发旧日期也不乱 |
| 分类链接 | 全部写死指向 `other_blogs.html` | 由 `config.json` 的分类表决定 |
| 文件名 | 可被覆盖，也可写出目录 | 重名自动加 `-1`、`-2`；只允许 `blog/` 下的单层文件名 |
| 日期 | 按字符串排序 | 统一规范成 `YYYY-MM-DD` 再排序 |
| 草稿 | 无 | 本地自动保存 + `blog_draft/*.md` 磁盘草稿 |
| 体检 | 无 | `npm run check` / `npm run fix`，界面里也能修上下篇 |

## 安装与启动

需要 Node.js 18 以上。在 `blog_create` 目录里：

```bash
npm install
npm start
```

浏览器打开 <http://127.0.0.1:3000>。端口被占用时会自动尝试 3001、3002……

也可以指定端口：`node server.js --port=3080`。

> 这个工具只在本机运行、没有登录验证，请不要把它暴露到公网。

## 界面速览

- **左栏**：标题 / 日期 / 文件名 / 分类 / 作者 / 最后更新 / 关键词，正文编辑器，以及发布按钮。
- **右栏**：「预览」显示用站点真实 `blog_article.css` 渲染的效果；「结构」显示这篇会写到哪、上下篇是谁、
  字数统计与提示；「日志」记录每一次操作。
- **分类是点选式的**：分类芯片直接来自 `blog.html` 里实际出现过的分类 + `config.json`，悬停能看到对应
  分类页和篇数；点一下选中、再点取消，可多选。
  - 多分类会渲染成多个分类链接（例如 `音乐 / BanG Dream!`），上下篇按第一个分类归组（和站点现有做法一致）。
  - 需要新分类时，在芯片右侧输入框里输入并回车；它会被写进文章与总列表，但不会自动生成分类页，
    记得同时在 `config.json` 的 `categories` 里补一条映射。
- **最后更新**：可选。填了以后文章头部和站点列表里都会出现「最后一次更新：日期」。
- **字号 / 字体 / 颜色**：工具栏的「字号」「字体」「颜色」打开同一个面板，可以给选区设置字号（含自定义 px）、
  字体（宋体/黑体/楷体/仿宋/等宽）、文字颜色、背景色，以及段落对齐；带实时预览和常用色板。
- **图片**：工具栏「上传」或直接把图片粘贴 / 拖进正文，会自动存到 `blog_fig/<日期>/` 并插入；
  也可以点「图片」用外链地址，并设置宽度、图注。
- **阅读时长 / 体检**：底部实时显示字数、图片数与预计阅读时间；「结构」里会提示图片缺 alt、
  本地图片不存在、占位链接等问题。
- **文件名**：默认跟日期同步，手动改过之后就不再自动变。发布时如遇重名，会自动改成 `2026-11-06-1.html`。
- **格式**：默认 Markdown。切换成「原始 HTML」后工具栏会插入 HTML 标签，适合继续改老文章。
- **分段**：「自动」会在有连续空行时按标准 Markdown 分段，否则视作“一行一段”。也可以手动指定。
- **更新站点列表**：勾选（默认）时，发布同时写入 `blog.html` 和对应分类页。取消勾选就只生成文章文件。
- **更新文章**：从「打开文章」载入的老文章会进入更新模式，按钮变成「更新文章」，发布时覆盖原文件，
  不会产生重复条目。

## 快捷键

| 组合 | 作用 |
| --- | --- |
| `Ctrl + B` / `Ctrl + I` | 加粗 / 斜体 |
| `Ctrl + K` | 插入链接 |
| `Ctrl + S` | 保存草稿（`blog_draft/`） |
| `Ctrl + Enter` | 发布 / 更新 |
| `Tab` | 插入两个空格 |
| `Enter` | 列表、引用自动续行；空列表项再回车则结束列表 |

## Markdown 语法

````markdown
## 小节标题        →  <h3>（站点的正文标题样式）
### 子标题          →  <h4>

**加粗**  *斜体*  ~~删除线~~  ==高亮==  `行内代码`

- 无序列表         1. 有序列表
  - 缩进两格可嵌套
- [ ] 待办事项
- [x] 已完成事项

> 引用

```bash
代码块，可写语言
```

| 列 1 | 列 2 |
| --- | --- |
| 内容 | 内容 |

![说明](图片地址){50%}     ← 花括号里是宽度：50%、80%、300
[链接文字](地址)
---
````

说明：

- 标题会整体下移一级（`#` → `<h2>`，`##` → `<h3>`），避免和文章大标题同尺寸。可在
  `config.json` 的 `markdown.headingShift` 改成 `0` 关闭。
- 连续的纯图片行会自动合并进同一个段落，方便并排显示（`markdown.mergeImages`）。
- 直接粘贴的原始 HTML 会原样保留，因此旧文章照样能改。
- 裸链接（`https://…`）会自动变成可点击的链接。

## 字号 / 字体 / 颜色

工具栏的「字号」「字体」「颜色」打开同一个**文字样式**面板：

- **字号**：默认 / 小（0.85em）/ 大（1.15em）/ 特大（1.35em）/ 标题级（1.6em）/ 自定义 px。
- **字体**：宋体（衬线）、黑体（无衬线）、楷体、仿宋、等宽。
- **文字颜色**：8 个常用色板 + 取色器；点「默认」清除。
- **背景颜色**：7 个浅色色板 + 取色器，实现荧光笔效果；点「透明」清除。
- **段落对齐**：左 / 中 / 右 / 两端对齐（块级，会包一层 `<div style="text-align:…">`）。
- 「清除格式」只保留选区文字。

应用后会插入 `<span style="font-size:…;font-family:…;color:…;background-color:…">`，
Markdown 与原始 HTML 模式下都能用，预览实时生效。

## 图片上传

三种方式，效果一样：

1. 在正文里直接 **粘贴截图**（Ctrl+V）；
2. 把图片文件 **拖进** 正文；
3. 工具栏「上传」选择本地图片（可多选）。

图片会保存到 `blog_fig/YYYY-MM-DD/原文件名.png`，自动插入 `![名称](../blog_fig/日期/文件.png){80%}`。
支持 PNG / JPG / GIF / WebP，单张上限由 `config.json` 的 `maxUploadMB` 控制（默认 8 MB）。
上传目录可以用 `uploadsDir` 改，但改了之后预览路径也会跟着变。

## 更多格式

工具栏最右边的「更多格式 ▾」里还有一批排版片段，点击后会插入到光标处（Markdown / 原始 HTML 模式都能用）：

| 分组 | 项目 | 生成的 HTML |
| --- | --- | --- |
| 行内 | 下划线 / 高亮 / 上标 / 下标 / 键盘键 | `<u>` `<mark>` `<sup>` `<sub>` `<kbd>` |
| 行内 | 大字 / 小字 / 红色强调 | `<span style>` / `<font color>` |
| 段落 | 提示框 / 警告框 | `<div class="callout note">` / `.warn` |
| 段落 | 折叠块 | `<details><summary>` |
| 段落 | 两栏布局 | `<div class="columns">` + `.left` / `.right`（复用站点已有样式） |
| 段落 | 任务清单 | `- [ ]` / `- [x]`（Markdown）或 `<ul class="task-list">` |
| 图片 | 图片 + 图注 | `<figure>` + `<figcaption>` |
| 图片 | 双图 / 三图并排 | 一行内多个 `<img width>` |
| 媒体 | B 站视频 | `<div class="video-embed"><iframe …>` |
| 媒体 | 音频 | `<audio controls>` |

这些样式都写在 `blog_article.css` 里，插入的片段可以在「预览」里立刻看到效果。

## 发布时到底写了什么

1. `blog/<文件名>.html`：文章页（标题、时间、作者、分类、分享按钮、giscus 评论、上下篇）。
2. 相邻文章的上下篇区块：只有链接真的不一致时才改写，不会为了统一格式动老文章。
3. `blog.html` 与分类页（如 `game_blogs.html`）的 `#articles` 列表：按日期倒序插入；`【置顶】` 条目固定在顶部；
   填了「最后更新」的会在列表里显示出来。
4. `data.json`：登记 / 更新这篇的标题、日期、分类、文件名。
5. 发布前先做一遍内容体检，提示会写进日志和「结构」面板（不阻止发布）。

新增文章时还会写入 `<!-- prev-next:start -->` 标记，以后更新链接更精准；老文章没有标记也能识别。

## 命令行

```bash
# 从带 front matter 的 Markdown 直接生成
node cli.js build blog_draft/2026-11-06-标题.md --dry-run   # 只看结果不写文件
node cli.js build blog_draft/2026-11-06-标题.md

# 体检 / 修复
node cli.js check        # 文件、列表、上下篇是否一致
node cli.js fix          # 补登记缺的文章 + 修正上下篇链接
node cli.js fix --dry-run

# 新建草稿
node cli.js new "文章标题" --category=游戏 --date=2026-11-06

# 启动网页编辑器
node cli.js serve --port=3000
```

也可以 `npm run build -- <文件>`、`npm run check`、`npm run fix`。

草稿格式（`blog_draft/*.md`）：

```markdown
---
title: "文章标题"
date: "2026-11-06"
updated: "2026-11-20"
category: "音乐 / BanG Dream!"
author: "Jiaqi Z."
keywords: "linux vasp"
filename: "2026-11-06.html"
format: "markdown"
---
## 小节

正文……
```

## config.json

站点相关的设置都在这里，不需要改代码：

| 字段 | 作用 |
| --- | --- |
| `site.name` / `site.titlePrefix` | 站点名，以及文章 `<title>` 的前缀 |
| `author` / `defaultCategory` | 默认作者、默认分类 |
| `postsDir` / `indexPage` | 文章目录、总列表页（默认 `blog/`、`blog.html`） |
| `categories` | 分类 → 分类页文件名。不在表里的分类只会进总列表 |
| `giscus` | 评论配置；`enabled: false` 可整体关闭 |
| `indexUpdate.enabled` | 是否默认勾选「更新站点列表」 |
| `indexUpdate.pinnedKeyword` | 置顶标记（默认 `置顶`），列表里带这个字的条目不会被新文章挤下去 |
| `markdown.paragraphMode` | 默认分段方式：`auto` / `blank` / `line` |
| `markdown.headingShift` | 标题层级整体偏移，默认 `1` |
| `markdown.mergeImages` | 连续图片行是否合并成一段 |
| `uploadsDir` | 图片上传目录（默认 `blog_fig`，相对仓库根目录） |
| `maxUploadMB` | 单张图片大小上限（默认 8） |
| `server.port` / `server.host` | 默认监听地址 |

## 为什么上下篇以 blog.html 为准

旧版只把「本工具生成过」的文章写进 `data.json`，所以老文章不在里面。如果只按 `data.json` 排序，
新文章的“上一篇”就会跳过老文章。现在改为：

```
文章顺序 = blog.html 的完整列表 ∪ data.json（同名时 data.json 优先，且只认文件真实存在的）
```

这样补发一篇 2024 年的旧文章也不会乱。`data.json` 仍然保存每篇文章的元信息，`npm run fix`
可以把 `blog.html` 里有、`data.json` 里没有的文章补登记进去。

## 常见问题

**端口被占用？**
会自动往后找可用端口，控制台会打印真实地址；也可以 `--port=xxxx`。

**发布后分类页没变化？**
检查 `config.json` 的 `categories` 里有没有这个分类；没有的话只写总列表，日志里会有提示。

**想改已发布文章的标题/日期？**
「打开文章」载入后直接改，发布时选“更新文章”。改日期会让上下篇自动重排。

**文件名重复了？**
新建时自动加 `-1`、`-2` 后缀；想强制覆盖同名文件请用 CLI 的 `--overwrite`。

**预览里的图片/背景不对？**
预览会走 `/site/…` 读取站点自己的 CSS 和背景图；外链图片需要联网。粘贴上传的图片会走
`/site/blog_fig/…`，如果改了 `uploadsDir` 又看不到，检查该目录是否在仓库根目录下。

**粘贴图片没反应？**
粘贴时剪贴板里必须是图片（截图）；Word/网页复制的图片有时只有 HTML 没有图片数据，这时请先存成文件再拖进来。

**上传的图片会进 git 吗？**
会。`blog_fig/` 是站点自己的目录，没有被 `.gitignore` 忽略，方便随站点一起发布；不想提交的话可以自行忽略。

**字号/颜色对老文章也生效吗？**
样式是写进正文的 `<span style>`，只影响被包裹的那一段，不会改变全站默认字体。

**写了 `<script>` 会怎样？**
内容按可信处理，会原样输出。这个工具只在本机用，请不要把它当公共编辑器。
